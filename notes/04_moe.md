# CS336 课程笔记 04：详解混合专家模型 (Mixture of Experts - MoE)

---

## 1. MoE 核心概念与实证收益

在 2025 年，混合专家模型（MoE）已成为最前沿大模型（如 DeepSeek V3、Grok、Mixtral、LLaMA 4）的核心底座架构。

### 1.1 什么是 MoE
* **常见的认知误区**：
  许多人直觉上认为 MoE 是语义层面的“领域专家”——比如专家 1 专门负责解数学题，专家 2 专门写 Python 代码，专家 3 负责说法语。
* **技术本质**：
  MoE 是一种**稀疏激活的架构设计模式**。
  在传统的密集型（Dense）Transformer 模型中，每个 Token 在通过每一层时，都必须完整地经历相同的多层感知机（MLP / FFN）进行特征非线性映射。
  而 MoE 将这块庞大的 MLP 切分/复制为多个结构相同的子模块（称为**“专家 - Experts”**）。在每一层前向传播时，引入一个轻量级的网络——**“路由器（Router）”**，为每个 Token 动态计算概率，并仅将其分配给最适合它的 $k$ 个专家（通常 $k=1$ 或 $k=2$）。

![MoE 动态路由机制](images/moe_routing_mechanism.drawio.png)

### 1.2 MoE 的核心优势
1. **解耦参数量与单 Token 计算量 (FLOPs)**：
   大模型时代的黄金法则之一是：模型的“记忆能力”与模型总参数量强相关。
   通过 MoE 结构，我们可以把模型总参数量做大到数百亿甚至数万亿（通过复制专家），但因为每个 Token 只需要激活其中的 1~2 个专家，其前向计算所消耗的 FLOPs 几乎与小得多的密集型模型持平。
2. **在给定计算预算下性能显著占优**：
   实证表明，在相同的训练 FLOPs 预算下，MoE 模型不仅收敛速度远快于 Dense 模型，而且能取得更低的测试集困惑度（Perplexity）。
3. **专家并行性 (Expert Parallelism, EP)**：
   由于专家之间是完全独立的，我们可以把专家 1~4 放到 GPU 0，专家 5~8 放到 GPU 1，天然实现了分布式存储与计算，为模型扩展提供了新的维度。

## 2. 路由器设计空间与 Top-K 路由数学表达

路由器（Router）是 MoE 模型中负责非线性路由决策的核心层。

### 2.1 Top-K 路由数学公式拆解

对于输入的单个 Token 特征向量 $x$，路由和输出合并的计算逻辑如下：

#### 1. 亲和力评分 (Affinity Scores) 公式
$$S(x) = \text{Softmax}(x W_g)$$

* **$x \in \mathbb{R}^{d_{\text{model}}}$**：当前 Token 在残差主干上的隐藏特征状态向量，其中 $d_{\text{model}}$ 是模型的隐藏层通道宽度。
* **$W_g \in \mathbb{R}^{d_{\text{model}} \times N}$**：可学习的路由权重参数矩阵。其中 $N$ 是该 MoE 层中拥有的专家总数。
* **$x W_g \in \mathbb{R}^N$**：输入向量经过线性投影后，得到 Token 对每个专家的原始打分（Logits）。
* **$\text{Softmax}$**：归一化激活函数。它将原始打分转化为一个概率分布向量 $S(x) \in \mathbb{R}^N$，其所有元素非负且相加等于 1。每个元素 $S(x)_i$ 代表当前 Token 路由到第 $i$ 个专家的“亲和力概率”。

---

#### 2. 门控权重激活 (Gating Weights) 公式
$$G(x)_i = \begin{cases} 
  S(x)_i & S(x)_i \in \text{Top-k}(S(x)) \\
  0 & \text{otherwise}
\end{cases}$$

* **$G(x)_i \in \mathbb{R}$**：最终分配给第 $i$ 个专家的门控激活权重值。
* **$\text{Top-k}(S(x))$**：一个算子，它从概率向量 $S(x)$ 中挑选出数值最大的前 $k$ 个元素的集合。
* **分段函数含义**：如果第 $i$ 个专家的亲和力概率排在所有专家的前 $k$ 名内，则它的门控值就是对应的概率值 $S(x)_i$；否则，它的门控权重被强行置为 0（即该 Token 不会发给这个专家计算）。

---

#### 3. 专家输出加权合并公式
$$y = \sum_{i=1}^N G(x)_i \text{Expert}_i(x)$$

* **$y \in \mathbb{R}^{d_{\text{model}}}$**：当前 MoE 层输出的融合特征向量，将被加回残差主干。
* **$\text{Expert}_i(x) \in \mathbb{R}^{d_{\text{model}}}$**：第 $i$ 个专家（一个标准的 MLP 结构）接收输入 $x$ 后计算得出的输出特征向量。
* **求和项**：由于 $G(x)_i$ 在绝大多数专家上都为 0，实际的求和只涉及排名前 $k$ 的激活专家。这就实现了**稀疏计算**。

---

### 2.2 路由计算的数值精度 (FP32 Gating)
* **设计警示**：尽管大模型的整体网络在混合精度训练中常使用 FP16 或 BF16 以换取吞吐，但**路由器（Gating Router）的 Softmax 激活计算必须强制在 FP32（单精度浮点数）下执行**。这是因为 Softmax 涉及指数运算，在低精度（如 FP16）下极易因极值发生溢出或下溢，导致路由选择全 0 或 NaN。

### 2.3 路由器 Z-loss 正则化 (Router Z-loss)
* **设计直觉**：为了防止路由函数的 Softmax 输入（Gating Logits）无限制增大，在 MoE 训练中常常会加入一个额外的 Z-loss 正则化项。
* **公式定义**：
  $$\mathcal{L}_{z} = \frac{1}{B} \sum_{i=1}^{B} \left( \log \sum_{j=1}^{E} e^{h_j(x_i)} \right)^2$$
  其中 $B$ 是 Batch Size，$E$ 是专家总数，$h_j(x_i)$ 是针对第 $i$ 个输入 Token 在第 $j$ 个专家上的原始 Logit 分数。
* **物理意义**：该损失项对 Softmax 的配分函数 $Z = \sum_j e^{h_j(x_i)}$ 的对数值进行平方惩罚，迫使 Logits 始终在合理范围内波动，防止数值漂移。
* **启发性警示**：实验表明，如果移除路由器的 Z-loss，MoE 模型在训练几万步后，验证损失（Validation Loss）经常会出现巨大的尖峰甚至直接梯度崩溃，它是维持 MoE 训练稳定不可或缺的保护伞。

## 3. 训练稳定性与负载均衡 (Load Balancing)

### 3.1 崩溃陷阱：专家的“马太效应（富者更富）”

#### 🌟 通俗科普：什么是专家坍塌？
在 MoE 模型训练初期，路由权重 $W_g$ 是随机初始化的。
假设由于微小的随机性，专家 1 在处理某些 Token 时得到的初始打分略高于其他专家。
1. **正反馈更新**：路由器会倾向于把更多的 Token 派发给专家 1。
2. **强者愈强**：由于专家 1 接收了更多的训练数据，它的参数权重更新频率比其他闲置的专家快得多，能够迅速掌握更多的通用表征。
3. **退化崩溃**：随着训练进行，路由器发现专家 1 的能力确实比其他没怎么更新的专家强，于是把更多的 Token 塞给专家 1。
最终，这会导致**“马太效应 / 富者更富”**：所有的 Token 都在往少数一两个“明星专家”那里跑，其余 90% 的专家因为分不到数据而沦为僵尸参数，模型退化为纯密集型模型。这被称为**“专家坍塌（Expert Collapse）”**。

---

### 3.2 传统方案：辅助平衡损失 (Auxiliary Balance Loss)

为了强迫路由器均匀分发任务，Switch Transformer 等经典架构引入了辅助平衡损失：

#### 辅助平衡损失公式
$$\mathcal{L}_{\text{bal}} = N \cdot \sum_{i=1}^N f_i \cdot p_i$$

* **$\mathcal{L}_{\text{bal}}$**：加到总 Loss 中的辅助损失值。
* **$N$**：专家的总数。
* **$f_i$**：在当前 Batch 中，实际路由给专家 $i$ 的 Token 数量占总 Token 数量的比例：
  $$f_i = \frac{1}{B} \sum_{j=1}^B \mathbb{I}(\text{expert } i \text{ is in Top-k for } x_j)$$
  其中 $B$ 是 Batch 内的总 Token 数，$\mathbb{I}$ 是指示函数（当条件成立时为 1，否则为 0）。
* **$p_i$**：路由器对专家 $i$ 输出的归一化概率在当前 Batch 中的算术平均值：
  $$p_i = \frac{1}{B} \sum_{j=1}^B S(x_j)_i$$
* **物理意义与惩罚原理**：
  * 若 Token 完美地平均分发给各个专家，则对于每个专家，$f_i = 1/N$，$p_i = 1/N$。此时，损失值为最小常量值 1：
    $$\mathcal{L}_{\text{bal}} = N \cdot \sum_{i=1}^N \left(\frac{1}{N} \cdot \frac{1}{N}\right) = N \cdot \left(N \cdot \frac{1}{N^2}\right) = 1$$
  * 若发生专家坍塌（所有 Token 全挤在专家 1 身上，其他为 0），则 $f_1 = 1$, $p_1 = 1$，其余均为 0，损失值会直接暴增为 $N$：
    $$\mathcal{L}_{\text{bal}} = N \cdot (1 \cdot 1) = N$$
  通过在反向传播中最小化这一损失，我们强迫路由器吐出均匀的概率分布。

### 3.3 突破性创新：DeepSeek 无辅助损失再平衡 (Auxiliary-Loss-Free Routing)
虽然辅助损失解决了坍塌问题，但它存在一个巨大的副作用：**“强扭的瓜不甜”**。有些 Token 本身就不适合某些专家，强行塞过去会损害模型的整体表达精度。

DeepSeek 团队提出了一个革命性的方案，**完全不在反向传播中加辅助损失，而是采用在线的“物理天平调节”**：
1. **引入偏置分数 $b_i$**：
   为每个专家引入一个动态调节的偏置值 $b_i$（初始化为 0）。
2. **调节路由选择**：
   在前向传播选择 Top-k 专家时，路由器使用**带有偏置的亲和力分数**：
   $$\text{Routed Experts} = \text{Top-k}\left( S(x) + \mathbf{b} \right)$$
   * 注意：**这个 $b_i$ 只用于决定 Token 去哪，不参与最后求和时的 $G(x)_i$ 门控权重计算**。因此完全不影响模型表征的乘法梯度流！
3. **在线动态梯度调节**：
   在每个 Batch 结束时，系统统计各专家的实际负载。
   * 如果发现专家 $i$ 拿到的 Token 偏少，则默默调大其偏置：$b_i \leftarrow b_i + \gamma$（让它在下一批更容易被选上）。
   * 如果发现专家 $i$ 拿到的 Token 太多，则默默调小偏置：$b_i \leftarrow b_i - \gamma$。
   * $\gamma$ 是一个极其微小的在线调节步长。

这种做法解耦了“选路平衡”与“梯度更新”，实现了真正无损的模型容量与极高的负载均衡度。

## 4. 细粒度专家与共享专家 (Fine-grained & Shared Experts)

DeepSeek 对 MoE 的第二个巨大贡献是重塑了专家的拓扑排布。

![DeepSeek 细粒度与共享专家架构对比](images/fine_grained_and_shared_experts.drawio.png)

### 4.1 细粒度专家 (Fine-grained Experts)
* **设计思想**：
  传统的 MoE（如 Mixtral）将一个专家的隐藏层通道宽度设得很大（例如 $4 d_{\text{model}}$）。
  DeepSeek 指出，这样粗粒度的划分限制了路由的灵活性。他们将一个大专家水平切分成 $N$ 个更小的微型专家（例如每个隐藏层宽度只有 $1 d_{\text{model}}$）。
* **优势**：
  在总参数量和计算 FLOPs 相同的前提下，路由器可以在更庞大、精细的小专家池子里进行更加灵活的交叉组合（如 Top-6 或 Top-8），这极大地增强了稀疏专家之间的表征特异性。

### 4.2 共享专家 (Shared Experts)
* **设计思想**：
  在以往的 MoE 中，所有专家都是稀疏路由的。
  这会导致一个问题：一些无论什么语言、什么任务都要用到的“通用常识”（例如句法结构、高频虚词等），会被每个稀疏专家都重复学习一遍，白白浪费了宝贵的专家参数空间。
  DeepSeek 强行拎出 1~2 个**永远处于激活状态、不参与选路的“共享专家（Shared Experts）”**。
* **优势**：
  所有 Token 必须经过共享专家计算，从而把通用的常识全部集中在这里学完。稀疏路由专家得以完全净化，专注于学习更垂直、更特异的专业知识。

## 5. 系统工程挑战：Token 丢弃 (Token Dropping)

在大规模分布式多卡训练 MoE 时，不同卡之间需要频繁利用 `All-to-All` 算子来跨卡收发 Token。
* **容量因子 (Capacity Factor)**：
  如果某张卡上的专家特别受欢迎，可能会有暴增的 Token 涌向该卡，导致这卡瞬间显存溢出或网络通信堵塞。
  为了在工程上强行对齐硬件，我们会为每个专家设置一个**硬性接收上限（Capacity）**。
* **Token Dropping 的代价**：
  如果涌向某个专家的 Token 数量超过了这一上限，多出来的 Token 将会**被直接“丢弃（Dropped）”**。
  被丢弃的 Token 将不会经过 FFN 层计算，而是直接通过残差连接（Residual Identity Connection）送往下一层。
  * **坏处**：这引入了严重的训练非确定性，且由于未经过非线性映射，被丢弃 Token 的特征提取质量会严重下降，损害最终模型精度。在最新一代大模型中，研究人员正通过大幅度调高 Capacity Factor 并结合动态流水线来尽量避免 Token 丢弃。
