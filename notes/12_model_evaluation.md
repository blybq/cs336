# CS336 课程笔记：12. 模型评估详解与前沿危机（Model Evaluation）

## 1. 评估的本质与现代评估危机
模型评估（Evaluation）看似只是简单的“输入 Prompt $\to$ 收集 Response $\to$ 计算指标”，但实际上它是大模型开发中最深刻、也最混乱的领域之一。评估直接决定了模型的优化方向（Goodhart's Law：当指标变成目标，它就不再是一个好指标）。

### 1.1 Andrej Karpathy 指出的评估危机
1. **静态基准饱和**：经典基准（如 MMLU）已基本被前沿模型“刷爆”（达到 90%+ 准确率），模型开发正面临“无试卷可考”的窘境。
2. **测试数据污染**：由于预训练语料库极其庞大且不透明，基准测试的题目（甚至标准答案）极易在无意中泄露进训练集，导致“高分低能”的假象。
3. **主观评估的局限**：人工评估（如 Chatbot Arena）正在遭受“排行榜幻觉”（通过优化回复长度、迎合人类偏好的语气等手段操纵人类偏好）的侵蚀。

### 1.2 现代评估排名平台
- **Artificial Analysis**：绘制**“智能指数 vs. 推理成本”**的帕累托前沿（Pareto Frontier），展示模型在性价比维度的真实表现。
- **OpenRouter 排行榜**：通过统计付费用户在网关路由中主动选择各模型的 Token 消费量，从商业实际使用角度为模型排名。
- **Chatbot Arena**：盲测 A/B 平台，通过收集人类偏好计算 Elo 得分。

## 2. 评估的系统性框架

1. **输入端（Input）**：
   - Prompt 的来源与代表性。题目是过于简单（任何 LLM 都能答对），还是关注了长尾分布中的极端样本？在多轮对话中，输入是静态的（固定的测试集）还是动态的（随模型的上文输出而改变）？
2. **执行端（Execution）**：
   - 提示词工程的影响：Few-Shot（少量样本） vs. Zero-Shot（零样本），Chain-of-Thought（思维链），RAG（检索增强）或工具调用。
   - **关键警告**：我们是在评估**语言模型本身的能力**，还是在评估**围绕模型搭建的提示工程系统**？
3. **输出端（Output）**：
   - 评估准则的制定：精确匹配（Exact Match）、F1 值、代码执行通过率（Pass@1）或是人工评分。在实际部署中，还需要将生成错误的严重程度（如无害错误 vs. 灾难性安全事故）纳入惩罚权重。

## 3. 困惑度（Perplexity, PPL）评估法

自回归语言模型本质上是估计词序列的联合概率分布。

### 3.1 数学原理与分布匹配
假设数据集的真实数据分布为 $T(x)$，模型的估计分布为 $P(x)$。
- 语言模型的交叉熵损失为：
  $$H(T, P) = - \sum_{x} T(x) \log P(x)$$
- 困惑度定义为交叉熵的自然指数：$\text{PPL} = e^{H(T, P)}$。
- 根据信息论，交叉熵可以写为：
  $$H(T, P) = H(T) + D_{\text{KL}}(T \parallel P)$$
  其中 $H(T)$ 是数据集的固有熵，$D_{\text{KL}}$ 是 KL 散度。
- **结论**：最小化 PPL 等价于最小化模型分布 $P$ 与真实分布 $T$ 之间的 KL 散度。当 $P = T$ 时，PPL 达到物理极限最低值。通过最小化每个 Token 的预测概率，我们实质上在逼近通用智能。

---

### 3.2 困惑度（Perplexity, PPL）黑盒评估的作弊漏洞
* **设计警示**：当第三方对商业模型 API 进行 PPL 评估时，通常只能通过接口获得模型对下个词的预测概率。如果接口不够透明，模型提供方非常容易通过“作弊”或软件 bug 来干扰评估：例如，直接输出一个恒定的概率（如对所有词都输出 0.8），只要概率总和不等于 1 即可。
* **防作弊机制**：严密的评估方案必须要求 API 必须同时输出整个词汇表（Vocabulary）所有 Token 的对数概率（Log-probabilities），评估端在接收后应主动验算其概率指数求和是否严格等于 1（即满足概率分布约束 $\sum_{v \in V} P(v) = 1$），从而堵住这个黑盒评估漏洞。

## 4. 经典知识类基准测试与多选题位置偏差（MCQ Position Bias）

在大模型评估中，多项选择题（Multiple-Choice Question, MCQ）是最常用的评估格式（如 MMLU）。然而，这种评估方式面临着模型特有的**位置偏差（Position Bias）**问题。

### 4.1 什么是 MCQ 位置偏差？
在多选题评估中，大语言模型常常表现出强烈的**选项位置偏好**。例如，即使题目选项的语义内容完全一致，模型也可能会表现出**显著偏爱选项 A（或 B）而排斥选项 D** 的行为。

#### 为什么 LLMs 偏爱 A 超过 D？
1. **训练语料分布偏差（Prior Bias）**：
   - 在互联网语料库（考试题、网页文本、书籍）中，正确答案或选项的排列分布并不是绝对均匀的。选项 "A" 作为首个选项，在文本中出现的概率以及作为正确答案的先验频率往往高于其他选项，模型在无监督预训练阶段潜移默化地学到了这一统计先验。
2. **注意力机制的近因/首因效应（Primacy / Recency Effect）**：
   - Transformer 的因果注意力掩码（Causal Mask）和相对位置编码（如 RoPE），会使模型对文本开头的词（首因效应）或最接近输出的词（近因效应）产生不同的注意力权重偏置。选项 A 通常位于最前列，更容易受到注意力优先级的优待。
3. **Logits 激活空间偏置**：
   - 当我们强制模型只输出单个 Token（A、B、C 或 D）时，我们实际上在对比这四个 Token 对应的输出 Logits。由于 Token ' A'（带空格或不带空格）在分词器（Tokenizer）中的 ID、先验频率与其他字符不同，其 Logit 基线天然更容易被激活。

### 4.2 选项洗牌（Option Shuffling）如何缓解位置偏差？
为了测出模型对知识的真实掌握度，而非空间位置的偏好，工业界引入了**选项洗牌（Option Shuffling）**机制。

#### 具体实施路线：
1. **排列组合生成**：
   - 对于包含 4 个选项（$X, Y, Z, W$）的一道题目，不仅以原始顺序 $A=X, B=Y, C=Z, D=W$ 评估，还要将选项内容进行乱序排列（如生成循环位移排列，或全部 24 种全排列）。
2. **多视角前向评估**：
   - 将不同排列顺序的 Prompt 分别送入模型，收集模型在每个排列下对 $A, B, C, D$ 四个 Token 的预测概率（Logits）。
3. **概率重对齐与融合**：
   - **语义对齐**：将概率映射回其背后的真实语义选项。例如，在排列二中，选项 A 代表 $Y$。
   - **集成决策**：
     - **概率平均（Probability Averaging）**：将各语义选项在所有排列下得到的预测概率进行求和平均，选择均值最高的语义选项作为最终答案。
     - **多数投票（Majority Voting）**：让模型在每种排列下做单选，最后统计所有排列输出中最多次被选中的语义选项。
- **效果**：选项洗牌通过在空间位置上“对称化”模型的偏好，将由于空间偏好带来的虚高或虚低分滤除，极大地提高了 MCQ 评估结果的稳定性和信度。

## 5. 数据污染（Data Contamination）与检测技术

数据污染是现代大模型评估中最棘手的“作弊”行为。

### 5.1 什么是数据污染？
数据污染是指**评估测试集（Test Set）中的题目、上下文或标准答案，被无意或有意地包含在模型的预训练或微调（SFT）数据集中**。
- **后果**：被污染的模型可以通过简单的“记忆”和“背诵”在基准测试上拿到极高的分数，但其真正的泛化能力并没有提升。这种高分低能的现象严重扭曲了模型的真实技术水平。

### 5.2 如何检测数据污染？
由于模型厂商的预训练数据集通常是商业机密，我们无法直接用 Grep 匹配训练集。目前主要采用以下两种非侵入式检测方法：

#### 1. 精确子串匹配法（Exact Substring Matching / n-Gram Overlap）
- **原理**：基于测试集与大模型生成文本或公开训练集样本之间的文本重叠度。
- **实现**：
  - 将测试集的题目切分为 $n$-gram（如 13-gram，即连续 13 个单词或 Token 组成的子串）。
  - 如果大模型可以在给定前缀的情况下，以极高概率（甚至 $100\%$ 精确度）复现测试集中后续的超长子串，或者将测试集的一长段文字作为 Prompt 输入时，模型能只字不差地默写出下一段，则大概率判定该测试集已经被包含在其训练语料中。

#### 2. 困惑度偏移法（Perplexity Shift / Loss Anomalies）
- **原理**：未见过的干净数据与见过的数据在模型输出的概率分布上具有截然不同的特征。
- **实现**：
  - 计算模型在目标测试集上的困惑度（Perplexity, PPL）。
  - **对照实验**：准备一组与测试集同分布但绝对未公开的新测试集（或对原测试集进行不改变语义的同义词替换/改写，即 Perturbed Dataset）。
  - **判定准则**：
    - 如果模型在原测试集上的 PPL 显著低于改写后的测试集（表现出异常陡峭的 PPL 下降，即 **PPL Shift**），这说明模型记住了原测试集的精确文本字符顺序。
    - 通过绘制所有样本的 Token 似然概率分布图，如果发现部分测试样本的概率谱线中出现了异常低的极小值（极低交叉熵），说明这些样本在训练中被模型反复看过。

## 6. 前沿评估基准与安全对齐

### 6.1 高难度与前沿基准
- **GPQA**：博士级难度的物理、化学、生物选择题。PhD 专家正确率仅为 $65\%$，普通人使用谷歌搜索也只能拿到 $30\%$。
- **SWE-bench**：要求智能体（Agent）自动定位 GitHub 代码库中的 Issue 并提交 Patch。是目前评估大模型解决真实工程问题能力的黄金基准。
- **ARC-AGI**：抽象与推理挑战。完全不依赖语言记忆，通过图形变换考查模型的少样本泛化和推理能力。

### 6.2 安全性评估与能力分裂
- **能力（Capacity）**：模型知道如何做坏事（如写一段木马脚本，这由预训练获得）。
- **倾向性（Propensity）**：模型是否愿意配合用户的恶意提问（这由 RLHF 对齐获得）。
- **警示**：对于开源大模型，安全倾向性拦截是极其脆弱的。研究表明，只需花费几美元对开源模型进行少量的无害数据微调，即可彻底剥离其安全倾向性，释放出底层的有害能力。
